# Единая модель запуска/автозапуска обхода (plug-and-play)

Дата: 2026-09-21. Статус: утверждён и реализован (см. progress.md, раздел
«plug-and-play: единая модель запуска/автозапуска»).

## Проблема

Три пользовательские жалобы на поведение 1.2.0:

1. После «Сделать автостартом» для лучшей стратегии её нельзя запустить
   «прямо сейчас», пока не снимешь галочки «запуск службой» и «автозапуск
   с Windows».
2. Программа ругается на winws, который запущен ею самой.
3. Во время теста постоянно показывается «zapret запущен не от нашей программы».

### Корни

- `set_best_strategy` пишет `autostart_mode=profile`/`autostart_profile`, но
  задачу планировщика (`boot_app`) НЕ создаёт. Настройка висит мёртвым грузом:
  при входе ничего не стартует, в настройках текст «Автозапуск не включился».
  «Запустить сейчас» и «автозапуск» не связаны между собой.
- Механизмы автозапуска разнесены по командам (`install_service` vs
  `set_boot_app`) с взаимными ошибками-тупиками, которые пользователь должен
  разгребать вручную.
- Watchdog (`spawn_watchers`) считает `external=true`, когда winws жив, а
  `runtime` и служба «не знают» о нём — включая winws РАННЕГО ТЕСТА. Отсюда
  ложные «вне программы» и активная кнопка «Остановить», которая во время
  теста глушила бы его запущенный winws.

## Цели

- Любое действие всегда приводит к осмысленному состоянию (без тупиков).
- «Применить лучшую стратегию» = один клик: включить автозапуск И запустить
  сейчас.
- Программа никогда не называет «внешним» процесс, запущенный ею, службой
  или тестом.
- Механизм автозапуска (служба ↔ задача планировщика) всегда один.
- Не трогаем обновления, DNS, Telegram (вне жалобы).

## Модель состояния

```rust
enum WinwsOwner { None, App { profile_id }, Service { profile_id },
                  Test, External }
```

`winws_owner(data_dir, runtime, service_running, service_strategy, testing)`,
порядок приоритета:

1. `testing` → `Test` (тест гоняет свой winws намеренно).
2. `runtime` жив (`via=app`) → `App{profile}`.
3. `service_running == Some(true)` → `Service{strategy}`.
4. есть winws и среди них свой (`own_engine_pids` непуст) → `External`.
5. иначе → `None`.

Watchdog пишет `external_winws = owner == External`. Условие пресекает ложно
положительные срабатывания во время теста и для своей службы.

## Семантика команд

### `start_profile(id)` — «Запустить/переключить»
- Если служба установлена: остановить прямой runtime (если был), пересоздать
  службу под профиль id (`svc::install_service` — уже идемпотентен:
  stop+delete+create+start) и запустить её. Состояние: `service_running=true`,
  `service_strategy=id`, `runtime=None`. Тост «служба переключена на <имя>».
- Иначе — существующий прямой `do_start` (собственный winws под GUI).

### `apply_best_strategy(id)` — замена `set_best_strategy`
- Профиль существует → `autostart_mode="profile"`, `autostart_profile=id`,
  `testCache.best_id=id`.
- Служба установлена → мой же службу на id (как `start_profile`).
- Иначе → создать задачу планировщика (если ещё нет) + запустить сейчас
  (`do_start`).
- Тост: «лучшая стратегия: автозапуск включён и запущена сейчас».

### `install_service(id)` — пользователь включает службу
- Если была задача планировщика — снять её автоматически (`boot_app=false`).
- Репоинт+старт службы (как сейчас). Без ошибки-тупика на `boot_app`.

### `remove_service()`
- Снять службу. `service_* = None`.
- Сохранить `autostart_mode/profile`; перейти на программный автозапуск
  (создать задачу планировщика), если профиль задан. Если не задан —
  автозапуск остаётся выключенным.

### `set_boot_app(true)` (внутренний, по reconcile)
- Если служба установлена — сначала снять её автоматически, потом создать
  задачу. Внешний пользовательский вызов не нужен: переключение механизма
  делает `sync_autostart`.

### `sync_autostart()` — единая точка согласования
Вызывается после: старта программы, изменения настроек автозапуска,
`install_service`, `remove_service`, `apply_best_strategy`.

- Служба установлена → убрать задачу планировщика (`boot_app=false`).
- Нет службы:
  - профиль автозапуска задан и существует → создать задачу (если нет);
  - профиля нет → убрать задачу (если есть).

Инвариант: **«задача планировщика существует» ⇔ «программный режим и задан
профиль автозапуска»**.

## Frontend

- `renderRunBar` — по `winws_owner` на стороне фронта (данные уже в
  `B.runtime`/`B.service.running`/`B.external`/`testState.running`):
  - тест → «Идёт тест стратегий…», «Остановить» скрыт (есть свой стоп теста);
  - служба → «Служба: <имя>», стоп = `stop_running`;
  - внешний/свой runtime → как сейчас.
- Плитки профилей: активность по runtime ИЛИ службе (`runtime.profileId==p.id`
  ИЛИ `service.running && service.strategy==p.id`); кнопка «Запустить/Остановить».
- Тест-карточка: кнопка «Сделать автостартом» → «Применить: автозапуск +
  запустить сейчас», вызывает `apply_best_strategy`.
- Карточка «Автозапуск»: селект = «какая стратегия при входе»
  (`autostart_profile`), чекбокс «службой (без программы)» — переключение
  механизма. Бэкенд сам разводит задачу/службу через `sync_autostart`.
  Убрать недостижимые тексты («сначала отключите автозапуск» и т.п.).

## Удержание целостности совместимости теста

- `test_strategies` останавливает всё и возвращает прежний режим (runtime или
  службу). При службе возврат = `svc::start_service` (стратегия службы не
  менялась тестом) — без изменений.
- Во время теста watchdog не трогает `external_winws` и не роняет runtime.

## Тесты

- Юнит: `winws_owner` (приоритеты всех веток), `autostart_plan` (решение
  sync_autostart как чистая функция), удаление тупиков (install_service при
  boot_app; set_boot_app при службе).
- Регрессия: существующие 47 тестов остаются зелёными.

## Риски

- Репоинт службы = UAC на каждую смену профиля при headless-режиме (редкий
  случай, приемлемо).
- `apply_boot_task` требует exe-путь и может не сработать без прав — reconcile
  best-effort с логом.
