# Z GUI — правила работы агентов (AGENTS.md)

Проект: GUI для DPI-bypass-движков (flowseal zapret, zapret2, GoodbyeDPI, DPIBreak) на **Rust/Tauri + vanilla JS/Vite**.

## Карта проекта (читать перед любыми правками)

- `src/main.js` (~110 KB) — ВСЯ логика фронтенда одним файлом. Крупнейшая зона риска.
- `src/styles.css` (~35 KB) — стили.
- `src-tauri/src/*.rs` — бэкенд Tauri, 19 модулей: `lib.rs`, `runner.rs`, `service.rs`, `config.rs`, `presets.rs`, `profiles.rs`, `updater.rs`, `tester.rs`, `netreset.rs`, `dns.rs`, `watchdog.rs`, `telegram.rs`, `embedded.rs`, `human.rs`, `logger.rs`, `diag.rs`, `texts.rs`, `tools.rs`, `main.rs`.
- `src-tauri/crates/tg-ws-proxy-rs` — локальный крэйт (websocket-прокси).
- `data/`, `dist/`, `release/`, `node_modules/`, `src-tauri/target/`, `src-tauri/gen/` — **сгенерированное и мусор, 35 ГБ**. НЕ читать, НЕ анализировать, НЕ включать в контекст. Весь размер репо — артефакты билда, исходников в проекте ~2 МБ.

## Обязательный процесс перед каждым изменением (воронка)

1. **Карта, не весь код.** Если задача затрагивает неизвестную зону — сначала только структура и токен-вес файлов через Repomix MCP (`repomix` инструменты) или `Get-ChildItem`/`grep`. Никогда не открывать весь `main.js` или модуль `.rs` целиком «на всякий случай».
2. **Точечное чтение.** Читать только нужные файлы/функции через Read/Grep с диапазонами строк. Мегабайты в контекст = захлёбывание модели и ломаный код.
3. **Проверка перед утверждением.** Любое утверждение о коде (имя функции, сигнатура, путь, поведение) — только после Grep/Read. Не проверил — скажи «не проверял».
4. **Прогон сборки перед ответом «готово».** Rust — `cargo check` (и `cargo clippy` при рефакторинге) в `src-tauri/`. JS — `npm run build`. Без зелёной сборки задача не считается завершённой, а «готово» не пишется.
5. **Локальные проверки.** Ничего не убирать и не рефакторить без проверки, что существующее поведение не сломалось: логика — self-check функции/мини-тест. Прикладной запуск приложения пользователь делает сам (`npm run tauri dev` запускает только он, он же подтверждает результат визуально).
6. **Дифф-гейт.**
   - Никакого мусорного/мёртвого кода, no-op-веток, закомментированного кода.
   - Новый функционал — минимум кода, правильный тип, обработка ошибок.
   - Не дублировать уже существующие функции (сначала grep по названию).
   - Ломанные/несвязные правки — самому перечитать свой дифф и переделать, а не ждать, что «пользователь примет как есть».

## Ответственность агента

- Спор с пользователем про факты запрещён: не доказал грепом — признай «проверю и уточню», а не настаивай на выдумке.
- При сомнении в архитектуре (куда класть код) — спрашивать, но с конкретикой: 2-3 варианта и рекомендация.
- Исправление багов — искать корень, не симптом. Смотреть всех вызывающих перед правкой функции.
